# 접근성 검사 결과 갱신

1. Java와 Nu Html Checker 공식 배포판의 `vnu.jar`를 준비합니다. https://validator.github.io/validator/
2. 프로젝트 루트에서 `VNU_JAR=/절대경로/vnu.jar yarn audit:accessibility`를 실행합니다.
3. 개발 서버를 재시작하거나 다시 빌드한 뒤 `/component-guide/accessibility-exceptions`의 최근 검사 결과를 확인합니다.

명령은 운영 빌드를 만든 뒤 로컬 전용 서버(기본 3099, `AUDIT_PORT`로 변경)를 실행합니다. 레지스트리에 등록된 기업·기관 중 페이지가 존재하고 placeholder가 아닌 화면을 중복 없이 검사합니다. HTML을 외부 서비스에 전송하지 않습니다. 현재 빌드의 초기 HTML만 검사하므로 모달 열림 등 조작 후 DOM은 별도 검사해야 합니다.

모든 화면의 HTTP 응답과 검사기 JSON을 확인한 뒤 결과를 `src/content/publishing-guide/accessibility-audit.json`에 한 번에 저장합니다. 검증 오류는 결과에 기록하지만 서버·검사기 실패나 검사 중 소스 변경은 실행 실패로 처리하고 기존 결과를 유지합니다. 결과 파일은 다른 작업 변경 사항과 함께 검토해 배포합니다. 이 명령은 커밋하거나 푸시하지 않습니다.

화면의 최신 여부는 빌드 시점의 소스 지문과 검사 시점의 지문을 비교합니다. 검사 결과 파일 자체는 제외합니다. 커밋하지 않은 변경도 반영되며, 결과 저장만으로 지문이 달라지지는 않습니다. 실행 중인 개발 서버에서는 소스를 변경한 뒤 서버를 재시작해야 비교 기준도 갱신됩니다. 소스 일치는 검사 통과를 뜻하지 않습니다.

기존 2026-08-24 기록과 원인 설명은 과거 참고 자료로 보존합니다. 자동 검사 결과는 오류 원문을 보존하며 자동으로 라이브러리 예외로 판정하지 않습니다. WAVE는 자동 검사 대상이 아니므로 현재 화면과 조작 상태를 별도 검사하고 검사일·버전·캡처를 증적에 기록합니다.

## 배포 자동 갱신

main 릴리스 워크플로는 메타데이터 생성 후 Java 21과 Nu Html Checker를 준비해 전수검사를 실행합니다. 실행 실패 시 배포를 중단합니다. 오류 발견 자체는 배포 차단 조건이 아니며, 결과와 미분류 오류를 검토해야 합니다. 결과 JSON을 릴리스 커밋에 포함한 후 다시 빌드하므로 배포 화면에도 같은 결과가 반영됩니다.

요약 카드·유형별 표·화면별 표는 결과 JSON 하나에서 계산합니다. 알려진 메시지만 기존 원인에 분류하며, 새 오류는 ‘원인 확인 필요’로 분리합니다. frontend-handoff에는 결과와 조회 화면만 전달하고 검사 실행 코드는 제외합니다.
